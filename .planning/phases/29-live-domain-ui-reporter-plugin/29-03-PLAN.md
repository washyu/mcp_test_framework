<objective>
Rewire `mcp-contracts run` to delegate the default domain-UI render to the in-subprocess reporter plugin landed in Plan 02. Three operator flag combinations to handle:

- **Default path** (no `-q`, no `--debug`): CLI passes `--mcp-domain-ui=force` to the pytest subprocess. The reporter inside the subprocess emits the entire domain UI (header + rows + summary). CLI does NOT re-parse JUnit XML for the default render. The default-path `render_domain_ui(parsed, ctx)` call at `cli.py:956` is **deleted** per D-05.
- **`-q` / `--quiet` path**: CLI passes `--mcp-domain-ui=off` to the subprocess (reporter stays silent). After subprocess returns, CLI parses the JUnit XML and calls `render_summary_only(parsed, ctx)` — the existing summary-only path is preserved. Per the gray-area resolution: `-q` behavior is preserved by keeping the JUnit parse code in CLI for this branch only.
- **`--debug` path**: CLI passes `--mcp-domain-ui=force` (reporter renders the default UI inside the subprocess) AND after subprocess returns, CLI parses the JUnit XML so `render_debug_appendix(stdout, stderr, parsed, xml_path=tmp_xml)` can extract ToolCallError properties and emit the appendix. Both renderings appear: reporter-driven domain UI from subprocess stdout, then appendix from CLI.

`parse_junit_xml` stays in `_runner.py` (D-05a, audit confirms ~50 test callers + CLI's surviving `-q`/`--debug` callsites). The CLI keeps the `tmp_xml` lifecycle (creation + finally-cleanup) because `-q` and `--debug` still need it. The `_dispatch_default_mode_or_error` pre-flight, exit code mapping via `_map_exit_code`, and `typer.Exit(code=mapped)` tail all SURVIVE — only the default-path render call is removed.

Purpose: This is the operator-facing payoff of REPORTER-01. After this plan, library-mode AND CLI-mode operators converge on the same render path (the reporter); the framework no longer has two rendering routes for the same default output.

Output: Surgical edits to `cli.py` (delete one render call, change argv composition), one signature tweak in `_runner.py:_build_pytest_args` (add `domain_ui_mode: str` kwarg), CLI-level tests.
</objective>
