Step 1 — Add the module-level helper `_build_pytest_args` immediately AFTER `_load_config` (insert at approximately cli.py:90, before the `@app.command(...)` decorator on `run`). Function shape, copied verbatim from 09-PATTERNS.md lines 100-114:

```python
def _build_pytest_args(
    junit_xml: Path | None,
    pytest_args: list[str] | None,
) -> list[str]:
    """Translate `--junit-xml=PATH` (Phase 09 D-01b public spelling) into pytest's
    `--junitxml=PATH` (no-dash internal spelling) and assemble the argv passed to
    ``pytest.main(...)``.

    D-01a precedence: the explicit flag is inserted BEFORE the passthrough
    forwarded args so a later passthrough ``--junitxml=...`` (after ``--``)
    wins under pytest's last-occurrence argparse rule. The helper does NOT
    de-duplicate or validate paths -- pytest's own argument handling is the
    single source of truth.

    L-03 invariant: this helper builds the argv list only; the call site in
    ``run`` keeps the bare ``raise typer.Exit(code=pytest.main(...))`` shape
    with NO try/except wrap (Phase 5 D-cli-flags-3).
    """
    forwarded = list(pytest_args or [])
    args: list[str] = ["tests"]
    if junit_xml is not None:
        args.append(f"--junitxml={junit_xml}")
    args.extend(forwarded)
    return args
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → CLI | The `--junit-xml=PATH` argument is operator-supplied. Path is forwarded verbatim into pytest's `--junitxml=PATH`; pytest writes the XML file. |
| CLI → pytest | `_build_pytest_args` constructs an argv list; `pytest.main` consumes it. No shell interpolation, no `os.system`, no subprocess. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `_build_pytest_args` argv construction | accept | The function uses an f-string `f"--junitxml={junit_xml}"` with `Path` (not raw str). Typer pre-validates the option type. No shell is involved — pytest receives a Python list and parses it via argparse. Operator-supplied paths are within the operator's own trust boundary; pytest is responsible for opening the file. |
| T-09-02 | Information Disclosure | JUnit XML at operator-chosen path | accept | The XML contains test names + skip reasons + failure messages — same content already visible in pytest's terminal output. No new information surface. Operator chooses where the file lands. |
| T-09-03 | Denial of Service | Operator passes a path to a write-protected directory | accept | Pytest's own filesystem error surfaces as a non-zero exit code; the framework does not pre-validate the path (matches Phase 5's choice to defer pytest argparse errors to pytest itself). Documenting this in the `--help` text is out of scope; pytest's own error message is sufficient. |
</threat_model>
