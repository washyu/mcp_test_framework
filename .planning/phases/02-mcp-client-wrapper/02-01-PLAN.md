<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS environment → Config() | Untrusted env-var values cross into a frozen Pydantic model; type/range coercion happens at the boundary. |
| YAML file → Config() | A user-supplied YAML overlay file (path from `MCPTF_CONFIG_FILE`) feeds the same model. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | Tampering | `MCP_SERVER_TIMEOUT_SECONDS` env var | accept | Field type is `int` with `ge=1`; pydantic raises `ValidationError` on non-int or `<1`. No code path uses the value beyond `asyncio.timeout()` (Plan 02), where a too-large value fails closed (just a longer wait). Risk: developer-controlled env var on developer machines — not an attacker-influenced surface. |
| T-02-01-02 | Information Disclosure | `.env.example` / `config.example.yaml` | accept | Files are documentation only and ship the SAME defaults as `models.py`. No secrets disclosed (timeout is non-sensitive). |
| T-02-01-03 | Denial of Service | `MCP_SERVER_TIMEOUT_SECONDS` set to a huge value (e.g., 99999) | accept | Phase 2 wrapper is consumed by tests only — a too-large ceiling makes a test hang up to the ceiling, then fail. No production surface. The `ge=1` lower bound prevents the more dangerous "0 = never time out" case (would still time out instantly under `asyncio.timeout(0)`, but pydantic rejects it). |
</threat_model>
