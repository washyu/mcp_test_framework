<objective>
Close **Gap-1** from `.planning/phases/17-schema-driven-codegen-surface/17-HUMAN-UAT.md`: a live `gen-sdet-classes` run against homelab-mcp produces 29 `reportUnusedImport` pyright errors across 27 generated files, violating **CODEGEN-04 / SC1** ("generated files compile under mypy/pyright with no errors").

**Root cause:** `src/mcp_test_framework/sdet/_codegen.py` lines 346-360 unconditionally emit `import typing` and `from pydantic import BaseModel, ConfigDict, Field`. Tools whose params resolve to only basic types (`str`/`int`/`bool`) and never trigger `typing.Any` degradation AND never need `Field(...)` annotations leave one or both imports orphaned. Pyright strict catches this.

**Gate-blindness:** The synthetic 5-tool fixture in `tests/framework/unit/test_codegen_typecheck.py::test_synthetic_generated_passes_pyright_strict` never produces the all-basic-types-no-Field shape — every fixture tool either degrades to `typing.Any` (enum_tool, oneof_tool, object_tool) or uses `Field(default=...)` (simple_tool's `count` with default=1) — so the gate didn't catch it.

This plan closes BOTH the emitter bug AND the fixture-coverage hole, so the regression cannot recur silently.

Purpose: Restore CODEGEN-04 / SC1 — every generated file pyright-clean under strict mode against real-world MCP schemas — and harden the synthetic gate against the shape that bypassed it.

Output: 
1. Conditional import-block emission in `_codegen.translate_tool()` (only emit `typing` / `Field` when the rendered body references them).
2. New emitter regression test pinning the "no unused imports" contract.
3. Extended synthetic typecheck fixture covering the all-basic-types-no-Field shape.
