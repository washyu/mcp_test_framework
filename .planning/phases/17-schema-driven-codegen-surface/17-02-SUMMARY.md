| ------------------------------------------------ | ----------------------------------------------------- | --------- |

## generate() Write-Ordering Contract

For Plan 17-04 (CLI) and Plan 17-05 (pyright typecheck test) consumers:

1. `server_slug(server_name)` -- raises `ValueError` on empty/all-non-identifier input (CLI maps to operator error)
2. `shutil.rmtree(out_root / slug, ignore_errors=True)` -- D-03 wipe
3. `(out_root / slug).mkdir(parents=True, exist_ok=True)`
4. For each `tool` in `sorted(tools, key=lambda t: t.name)`:
   - Call `translate_tool(tool, slug=..., timestamp=...)` to get `(source_text, degraded_n)`
   - Write `out_root/slug/<module_name(tool.name)>.py` with `encoding="utf-8"`
5. **Write `__init__.py` LAST** (Pitfall 5) -- partial states surface as `ModuleNotFoundError`, never half-imported. `__init__.py` carries CODEGEN-06 header, sorted per-tool `from .X import XParams, XResponse` lines, `__all__`, and `_REGISTRY: dict[str, tuple[type, type[ToolResponse]]]`.
6. Return `{"tools": N, "degraded_fields": M}` for the CLI's post-run digest line.

`timestamp=None` uses `datetime.now(UTC).isoformat(timespec="seconds")`; tests pass a fixed value for byte-identical idempotence verification.

## Decisions Made

- **Structural-only schema preflight (Rule 1 deviation; see Deviations section).** The plan suggested `Draft202012Validator.check_schema` for the preflight; running it on the unknown-type test case (`{"type": "color"}`) rejected the schema at preflight before reaching `_emit_field`, which contradicted `test_unknown_type_degrades`. Replaced with `_check_schema_structural` -- narrow checks (required is list; properties is dict) that catch malformed schemas without forcing every type token to be a JSON-Schema primitive. The full metaschema is too strict for the walker's "degrade unknown types, refuse only structurally broken schemas" contract.
- **PascalCase split regex (Rule 3 deviation).** The plan's `_NON_IDENT = re.compile(r"[^a-zA-Z0-9_]+")` keeps `_` as an identifier char, so `pascal_case("create_vm")` would split to `["create_vm"]` -> `"Create_vm"` (wrong: 5 of 15 slug tests would fail). Added a second regex `_PASCAL_SPLIT = re.compile(r"[^a-zA-Z0-9]+")` (no underscore in the keep-set) used only by `pascal_case`. `server_slug` and `module_name` still use the original underscore-preserving regex.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Replaced full metaschema preflight with structural-only check**
- **Found during:** Task 2 (GREEN phase, running `test_unknown_type_degrades`)
- **Issue:** The plan's `Draft202012Validator.check_schema(input_schema)` preflight rejects fields like `{"type": "color"}` as invalid JSON Schema (the metaschema enumerates valid `type` tokens). This contradicts D-02's contract that unknown type tokens DEGRADE to `typing.Any` with an `unknown type: <repr>` comment -- the unknown-type test expected `translate_tool` to return a source string, not raise `SchemaValidityError`.
- **Fix:** Replaced `check_schema` with `_check_schema_structural(tool_name, schema)` -- catches the narrow class of malformed schemas the walker cannot operate on (required not a list, properties not a dict). The metaschema-strict path was preserved in the module docstring for future reference.
- **Files modified:** `src/mcp_test_framework/sdet/_codegen.py`
- **Verification:** `test_invalid_schema_raises_loud` (required-not-a-list) still raises `SchemaValidityError`; `test_unknown_type_degrades` (unknown type "color") now reaches the degradation path. Both tests pass.
- **Committed in:** `9a25192` (Task 2 GREEN)

**2. [Rule 3 - Blocking] PascalCase regex split on underscore**
- **Found during:** Task 1 (GREEN phase verification)
- **Issue:** The plan listed `_NON_IDENT = re.compile(r"[^a-zA-Z0-9_]+")` and `pascal_case` used `_NON_IDENT.split(tool_name)`. Since `_` is in the keep-set, `"create_vm"` becomes a single part `["create_vm"]` -> `"Create_vm"`. 2 of 5 pascal-case tests failed (test_snake_case, test_leading_digit_guard).
- **Fix:** Added a second regex `_PASCAL_SPLIT = re.compile(r"[^a-zA-Z0-9]+")` (drops underscore from keep-set) used only by `pascal_case`. `server_slug` and `module_name` kept their original `_NON_IDENT` behavior (they want to preserve underscores as separators that survive into the output).
- **Files modified:** `src/mcp_test_framework/sdet/_slugs.py`
- **Verification:** All 15 slug tests + 11 doctests pass.
- **Committed in:** `5e9b2b6` (Task 1 GREEN)
