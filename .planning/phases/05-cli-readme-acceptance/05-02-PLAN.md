OPS-03 contract from Phase 04.1 (load-bearing):

- pytest's SIGINT handler triggers the fixture finalizer; the AsyncExitStack unwinds; `stdio_client._terminate_process_tree` kills `homelab-mcp.exe`.
- D-cli-flags-3: `run` does NOT add a try/except around pytest.main(). The OS exit code is whatever pytest returns (130 on SIGINT, 0 on green, 1+ on test failure, 2 on usage error).

Typer flag pattern for forwarded args (the canonical Typer recipe for `argv after --`):
```python
ctx_settings = {"allow_extra_args": True, "ignore_unknown_options": True}
@app.command(context_settings=ctx_settings)
def run(
    config: Path | None = typer.Option(None, "--config", help="..."),
    pytest_args: list[str] = typer.Argument(None, help="..."),
) -> None:
    forwarded = list(pytest_args or [])
    raise typer.Exit(code=pytest.main(["tests", *forwarded]))
```
NOTE: With `allow_extra_args=True`, Typer/Click collects positional args (including everything after `--`) into the `Argument` list. The `--` separator itself is consumed by Click and does NOT appear in the forwarded list.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User shell -> CLI | Untrusted argv crosses here (path strings, pytest flags after `--`) |
| CLI -> pytest.main() | We forward unsanitized argv-suffix to pytest; pytest itself parses and may reject |
| pytest -> homelab-mcp subprocess | Phase 4 fixtures own this; out of scope for `run`'s direct trust model |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Tampering | `pytest_args` forwarding | accept | A user can pass any pytest flag, including those that change collection (e.g., `-p no:cacheprovider`). This is by design — the whole point of `--` forwarding is to give pytest's UI surface untouched. The user is the only consumer of their own CLI; no privilege boundary is being crossed |
| T-05-02-02 | Denial of Service | pytest.main() | accept | A pytest hang must time out via the underlying SDK calls (asyncio.timeout in McpTestClient, httpx.Timeout in OllamaJudge). `run` deliberately does NOT add a wall-clock cap — pytest convention is "user runs it, user kills it" |
| T-05-02-03 | Information Disclosure | `_load_config` ValidationError | accept | Pydantic ValidationError messages can include field values (e.g., a malformed URL). For a developer CLI on a developer machine, this is the desired diagnostic surface (CONTEXT.md Discretion bullet 2) |
| T-05-02-04 | Repudiation | OPS-03 (SIGINT teardown) | mitigate | pytest's own SIGINT handler invokes finalizers; Phase 04.1's `mcp_client` fixture's AsyncExitStack unwinds in the same task that did __aenter__; `stdio_client._terminate_process_tree` kills the homelab-mcp subprocess. Verified by `tests/smoke/test_smoke_homelab_mcp.py` regression smoke (Phase 04.1) and Plan 05 UAT |
| T-05-02-05 | Elevation of Privilege | n/a | accept | `run` adds no privilege escalation — it runs pytest as the same user with the same env |
</threat_model>
