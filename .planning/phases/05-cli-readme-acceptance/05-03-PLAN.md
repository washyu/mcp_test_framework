    ```python
    async def _list_tools_async(cfg: Config) -> list[Tool]:
        """Drive the MCP client lifecycle on a single task.

        AsyncExitStack is technically redundant with the single-context
        `async with McpTestClient(...)` form, but it is used anyway to:
        (1) future-proof against adding a second resource (e.g., a logger handle),
        (2) explicitly mirror the Phase 04.1 ownership lesson,
        (3) keep __aexit__ semantics identical regardless of how many resources land.
        """
        async with AsyncExitStack() as stack:
            client = await stack.enter_async_context(
                McpTestClient(
                    cfg.mcp_server.command,
                    cfg.mcp_server.args,
                    cfg.mcp_server.timeout_seconds,
                )
            )
            return await client.list_tools()


    def _format_tools_text(tools: list[Tool]) -> str:
        """Indented-block text format: name on its own line, full wrapped description beneath.

        Width comes from shutil.get_terminal_size with an 80-col fallback
        (D-list-3 / Discretion). Stdlib textwrap.fill handles wrapping --
        no `rich` dependency.
        """
        width = max(40, shutil.get_terminal_size((80, 20)).columns)
        sorted_tools = sorted(tools, key=lambda t: t.name)
        if not sorted_tools:
            return "(no tools registered on the server)"
        blocks: list[str] = []
        for t in sorted_tools:
            desc = t.description or "(no description)"
            wrapped = textwrap.fill(
                desc,
                width=max(20, width - 2),
                initial_indent="  ",
                subsequent_indent="  ",
            )
            blocks.append(f"{t.name}\n{wrapped}")
        return "\n\n".join(blocks)


    def _format_tools_json(tools: list[Tool]) -> str:
        """Full MCP tool record per tool: {name, description, inputSchema, outputSchema}.

        Sorted alphabetically by name (D-list-4). Trailing newline so the
        output composes with shell pipelines. `default=str` is a defensive
        fallback for any non-serializable annotation values inside schemas.
        """
        sorted_tools = sorted(tools, key=lambda t: t.name)
        payload = [
            {
                "name": t.name,
                "description": t.description,
                "inputSchema": t.inputSchema,
                "outputSchema": getattr(t, "outputSchema", None),
            }
            for t in sorted_tools
        ]
        return json.dumps(payload, indent=2, default=str) + "\n"
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User shell -> CLI | Untrusted argv (path strings to `--config`, `--json` boolean) |
| CLI -> MCP subprocess (homelab-mcp) | stdio_client launches the configured `cfg.mcp_server.command` with `cfg.mcp_server.args`. The command name comes from env / .env / YAML — owner-controlled |
| MCP subprocess -> CLI stdout | The subprocess's tool definitions (name, description, schemas) flow through `Tool.model_validate` (mcp SDK Pydantic guard) before reaching CLI formatters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering | `cfg.mcp_server.command` | accept | The MCP server command comes from owner-controlled config (env/YAML/.env). A malicious env-var injection could point the CLI at a hostile binary, but the CLI is run BY the owner ON the owner's machine — same trust model as `bash -c "$MALICIOUS"`. Pydantic-settings does not eval the value |
| T-05-03-02 | Information Disclosure | `_format_tools_text` / `_format_tools_json` output | accept | Tool descriptions and schemas are intended to be displayed — they are the literal point of `list-tools`. No PII or secrets flow through this path |
| T-05-03-03 | Denial of Service | MCP subprocess hang | mitigate | `McpTestClient.list_tools()` wraps `session.list_tools()` in `asyncio.timeout(self._timeout_seconds)` (default 30s from `McpServerConfig.timeout_seconds`). A hanging subprocess raises `TimeoutError` instead of blocking forever |
| T-05-03-04 | Repudiation (OPS-03) | Ctrl+C subprocess teardown | mitigate | asyncio.Runner + AsyncExitStack-owned McpTestClient -> KeyboardInterrupt unwinds the runner's task -> `__aexit__` runs in same task that did `__aenter__` -> `stdio_client._terminate_process_tree` (mcp SDK) sends SIGTERM then SIGKILL on a 2.0s timer (Job Object on Windows). Verified by Plan 05 UAT (Get-Process homelab-mcp returns no matches). Reuses Phase 04.1's hardened pattern |
| T-05-03-05 | Tampering | JSON output `default=str` fallback | accept | If the MCP server returns a tool with a non-serializable `inputSchema` value (e.g., a Pydantic model leaked across the wire), `default=str` stringifies it. Worst case: lossy JSON; the offending tool is still visible. Better than crashing list-tools |
| T-05-03-06 | Pitfall 4 (Windows ProactorEventLoop) | asyncio.Runner on Windows | mitigate | Python 3.14 default loop on Windows is ProactorEventLoop (required for stdio_client subprocess support). `asyncio.Runner()` honors the platform default. Verified by Phase 04.1 same-task pattern shipped on Win11 |
</threat_model>
