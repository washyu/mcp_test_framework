# Phase 21.1 Plan 02: SDET generated output relocation — consumer wiring Summary

**`gen-sdet-classes` and `mcp_session` both consume `cfg.sdet.generated_root` directly; the fixture's load mechanism switches from `importlib.import_module` against the framework namespace to `importlib.util.spec_from_file_location` with `submodule_search_locations` against the on-disk slug dir. The framework no longer requires generated code to live under its own `src/` tree.**

## Confirmation of the submodule_search_locations kwarg use

The plan's non-negotiable design point (CONTEXT.md D-03 + PATTERNS.md "Critical sub-pattern") is preserved verbatim in `session.py`:

```python
spec = importlib.util.spec_from_file_location(
    pkg_name,
    init_py,
    submodule_search_locations=[str(slug_dir)],
)
```

Without this kwarg, the generated `__init__.py`'s relative imports (`from .echo_message import ...`) raise `ImportError: attempted relative import with no known parent package`. Pinned at `tests/framework/unit/test_session_loader_invariants.py::test_uses_submodule_search_locations`.

## Decisions Made

See `key-decisions` in the frontmatter. The most load-bearing decisions:
1. **`submodule_search_locations=[str(slug_dir)]` is non-negotiable.** Without it the relative imports inside the generated `__init__.py` (`from .<tool> import ...`) raise `ImportError`. Same pattern proven by `tests/framework/unit/test_codegen_integration_mock.py:_load_generated_init`.
2. **CWD-relative resolution for non-absolute paths, applied identically at both call sites** (`cli.gen_sdet_classes` and `sdet.session.mcp_session`). Consistent with the `MCPTF_CONFIG_FILE` precedent and means write-side and load-side resolve the same configured value to the same absolute path under any given CWD.
3. **Synthetic `pkg_name` prefix (`_mcptf_sdet_generated_{slug}`)** for sys.modules registration. Keeps fixture-loaded packages isolated from the framework's own importable namespace and avoids cross-invocation cache collisions.
