# Phase 21.1: SDET generated output relocation — make codegen output config-driven; remove SUT-specific code from src/ - Context

**Gathered:** 2026-05-14
**Status:** Ready for planning

<domain>
## Phase Boundary

The codegen output path is currently hardcoded to `src/mcp_test_framework/sdet/generated/<slug>/` ([cli.py:995](src/mcp_test_framework/cli.py:995)), and the SDET fixture imports it as a package-relative module `mcp_test_framework.sdet.generated.{slug}` ([session.py:50](src/mcp_test_framework/sdet/session.py:50)). As a result, 56 homelab-mcp-specific generated files are committed inside the shipped framework package — leaking a SUT into the framework's distribution and violating SEED-022 (framework primitives only; SUT knowledge belongs to the SDET).

Phase 21.1 delivers two coupled outcomes:

1. **Operator/SDET controls where generated classes land.** The output root is read from `config.yaml` (`sdet.generated_root`), required, with a SAFE-03-style fail-loud error on absence. Used by both the `gen-sdet-classes` CLI (as write target) and the `mcp_session` fixture (as import source). No CLI flag override, no env var override.

2. **`src/mcp_test_framework/sdet/generated/` is gone from `src/`.** The 56 `homelab_mcp/*.py` files and the `generated/__init__.py` namespace marker are deleted. Pyright include scope is reduced to drop the now-extinct subtree. Tests that referenced generated classes under that path are reworked (specifics deferred to plan-phase).

**Out of scope:** the SDET→test-code rename (SEED-023 — deferred to v1.4). The `sdet` namespace name survives this phase intact; only the `generated/` subtree relocates.

</domain>

<decisions>
## Implementation Decisions

### Configuration surface

- **D-01:** No default for the output path. `sdet.generated_root` is a **required** key in `config.yaml`; if it is absent or empty, `gen-sdet-classes` and the `mcp_session` fixture both emit a SAFE-03-style operator-tone error and exit 2. Matches the v1.2 fail-loud posture — the framework never silently invents paths to write into or load Python code from. Aligns with `project_config_discovery_and_safety` memory: missing config = loud error, not silent default.

- **D-02:** `config.yaml` is the **only** way to set the path. No CLI `--out` flag on `gen-sdet-classes`. No `MCPTF_GENERATED_ROOT` env var. One source of truth. Rationale: the path is a property of the project's test layout, not a per-invocation knob — SDETs set it once at setup. Also dodges the dotenv-silently-beats-config footgun captured in `project_dotenv_silently_beats_config` memory; adding another env-overlay knob now would repeat the v1.1/v1.2 mistake.

### Import strategy

- **D-03:** The `mcp_session` fixture loads the generated `__init__.py` via `importlib.util.spec_from_file_location` against `<sdet.generated_root>/<slug>/__init__.py`. **No `sys.path` mutation.** The framework owns the load mechanism entirely; the SDET's own test imports (`from tests.sdet._generated.homelab_mcp import CreateProxmoxVmParams`) are governed by the SDET's own package layout — not by anything the framework does. Smallest blast radius on framework code; cleanest separation between "framework loads `_REGISTRY`" and "SDET imports `<Tool>Params` in their test files."

### Migration of `src/mcp_test_framework/sdet/generated/`

- **D-04:** **Clean break.** Delete `src/mcp_test_framework/sdet/generated/homelab_mcp/` (56 generated files) and `src/mcp_test_framework/sdet/generated/__init__.py` (namespace marker). After this phase, the `src/mcp_test_framework/sdet/generated/` directory does not exist. Anything less leaves SUT code in `src/` and fails the phase title literally. Tombstone-redirect and gitignore-and-stop-writing alternatives were considered and rejected.

- **D-05:** Update `pyproject.toml` `[tool.pyright]` — remove `src/mcp_test_framework/sdet/generated` from both `include` and `strict` lists. Keep only `src/mcp_test_framework/sdet/response.py`. Generated code now lives outside `src/` and is operator-specific; pyright coverage of operator-managed generated output is not the framework's responsibility.

- **D-06:** Update CLI `gen-sdet-classes` echo strings, docstrings, and operator-error messages so they refer to `sdet.generated_root` and the configured path — not the old hardcoded `src/mcp_test_framework/sdet/generated/<slug>/`. The docstring, the "server identification failed" error detail line, and the post-success echo all currently leak the old path (3 sites).

- **D-07:** Update `src/mcp_test_framework/sdet/_tool_factory.py:21` docstring reference to `mcp_test_framework.sdet.generated.<slug>` — replace with neutral phrasing describing the configured generated root.

- **D-08:** Update `docs/SDET-AUTHORING.md` and `README.md` SDET sample so they reference the new config-driven path. Phase 21 just shipped these docs; Phase 21.1 corrects them as part of the same insertion sweep.

### Test rework (deferred to plan-phase)

- **D-09:** The 3 affected tests (`tests/framework/unit/test_sdet_fixtures.py`, `tests/framework/unit/test_gen_sdet_classes_cli.py`, `tests/sdet/test_proxmox_vm_lifecycle_readme_sample.py`) must not depend on a committed `homelab_mcp/` tree under `src/` after this phase. **The specific rework strategy is deferred to plan-phase** — planner chooses between (a) regen against live homelab-mcp into the new configured path during execution, (b) switch to synthetic-mock fixtures like [test_codegen_integration_mock.py](tests/framework/unit/test_codegen_integration_mock.py), or (c) a hybrid (mock for CI, live for an explicitly-marked subset). Constraint locked here; mechanism chosen at plan time.

- **D-10:** `tests/framework/unit/test_codegen_integration_mock.py` is **unaffected** — it already writes to `tmp_path` and uses synthetic tools; it never touched the `homelab_mcp/` tree. Survives the relocation unchanged. Confirms the codegen engine is already path-parametrized at `_codegen.generate(out_root=...)` — the only hardcoded sites are at the CLI and fixture wrappers.

### Claude's Discretion

- Exact wording of the SAFE-03-style error message for missing `sdet.generated_root` (subject to matching the `project_config_discovery_and_safety` operator-tone precedent).
- Whether `sdet.generated_root` is interpreted as project-root-relative or CWD-relative when not absolute — planner's call subject to matching `MCPTF_CONFIG_FILE` precedent.
- README sample wording for the new `sdet.generated_root` config snippet (subject to char-for-char parity with the renderer output already enforced in Phase 21 P02).
- Whether the deletion of `src/.../generated/` lands as one commit or splits across "CLI + fixture relocation" + "delete homelab_mcp/ tree" — planner's call, both are git-bisect-friendly.

</decisions>

## Existing Code Insights

### Reusable Assets

- **`_codegen.generate(out_root=Path, ...)`** ([_codegen.py:626](src/mcp_test_framework/sdet/_codegen.py:626)) — already takes the output root as a parameter; phase does NOT rewrite codegen. The 1-line edit at [cli.py:995](src/mcp_test_framework/cli.py:995) is the entire write-side change.

- **SAFE-03 fail-loud pattern** — already used by `_load_config(strict=True)` and the `MCP server command not on PATH` operator-tone error. New `sdet.generated_root` missing-config error reuses `_emit_operator_error(summary=..., detail=..., next_step=...)` with the same shape.

- **`server_slug()` from `_slugs.py`** — derives the per-server directory name. Survives unchanged; same slug logic applies to the new configured root.

- **Pydantic config model in `config.py`** — adding `sdet.generated_root: Path` as a required field follows the existing v2 config schema additions (cross-ref v1.2 SAFE-01..07 patterns).

- **`tests/framework/unit/test_codegen_integration_mock.py`** — the canonical pattern for mock-based codegen testing (Phase 20 deliverable). If the planner picks mock-based test rework for D-09, this file is the template.

### Established Patterns

- **`importlib.util.spec_from_file_location` for arbitrary-path loading** — standard Python pattern; no new framework primitive needed.

- **Wipe-and-write codegen output (Phase 17 D-03)** — survives unchanged. After D-01, the wipe target is `<sdet.generated_root>/<slug>/` instead of `src/.../sdet/generated/<slug>/`.

- **Operator-tone error pattern** — `_emit_operator_error(summary=..., detail=..., next_step=...)` is the established voice for fail-loud configuration errors. Reuse verbatim.

### Integration Points

- **`gen-sdet-classes` CLI** — reads `cfg.sdet.generated_root`, passes as `out_root` to `_codegen.generate`. The current 3 echo/docstring/error sites reference the new configured path.

- **`mcp_session` fixture** — reads `cfg.sdet.generated_root`, joins `<slug>/__init__.py`, loads via `spec_from_file_location`. Steps 1, 2, 4, 5 of the existing 5-step activation survive unchanged.

- **Config schema bump?** — depends on whether `sdet.generated_root` is a v2 additive field or whether a v2→v3 bump is warranted. **Defer to plan-phase**; adding a required field is technically a breaking change for any operator who never set it. Planner decides between a migration shim, a SAFE-03-style "missing required key" error with the upgrade hint, or a config schema version bump.

<specifics>
## Specific Ideas

- **Sample default path convention to recommend in docs:** `tests/sdet/_generated/` — colocated with `tests/sdet/` scenarios, underscore prefix signals "tool-managed, don't hand-edit." Recommended in `docs/SDET-AUTHORING.md` but **not enforced** by the framework (D-01 — no default means operators choose; the doc recommends one).

- **One config knob, not two.** Filesystem path is the user-facing form; the Python module path used by SDETs in their test imports is determined by their package layout, not by the framework. Avoids the "config has two keys that have to stay in sync" trap.

</specifics>
