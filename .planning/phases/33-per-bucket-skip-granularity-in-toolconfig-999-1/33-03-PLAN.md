<objective>
Extend the v1.1.1 collection-time skip pattern in `_plugin.py` to also drop per-bucket tests. Skipped buckets must be invisible to `pytest --collect-only` for the affected tool AND must not produce runtime SKIPPED rows.

Purpose: BUCKET-02 / SC#1. Same hotfix invariant as v1.1.1 / 260508-p0b (project memory MEM:project_v1_1_skip_bug): excluded tests are excluded at collection time, never via runtime `pytest.skip()`. The whole-tool filter already lives in `pytest_collection`; the per-bucket filter is a two-step pattern: (a) `pytest_generate_tests` filters the parametrize `names` list per test function via `TEST_FUNCTION_BUCKETS`, and (b) `pytest_collection_modifyitems` strips the `[NOTSET]` placeholder items that pytest 9.0.3 emits when an indirect parametrize call receives an empty list (this is the mechanism W2 revision had to correct — see Task 2 `<rationale>`).

Output:
- Per-bucket filter applied inside `pytest_generate_tests` (filters the `names` list per test function via `TEST_FUNCTION_BUCKETS`).
- `[NOTSET]` placeholder-item cleanup inside the existing `pytest_collection_modifyitems` (drops the single unparametrized item pytest synthesizes when indirect-parametrize is called with an empty list).
- Self-tests pinning BOTH collect-only absence AND full-run zero-SKIPPED for skipped-bucket cells. At least one subprocess-based collect-only test AND one subprocess-based full-run test are mandatory (W2/W3 fix); a synthetic-Metafunc unit test sits alongside for fast feedback.
</objective>
