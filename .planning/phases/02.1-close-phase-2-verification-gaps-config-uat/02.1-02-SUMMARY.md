# Phase 02.1 Plan 02: Reconcile config examples + repo hygiene Summary

Aligned `.env.example` / `config.example.yaml` / `pyproject.toml` `live_homelab` marker description to the canonical `uvx homelab-mcp` default invocation (D-01, D-02), gitignored the developer-local `config.yaml` (D-09), and committed the canonical spec at `docs/mcp_test_framework_mvp_spec.md` (D-10) — five files staged in two atomic commits, no code changes, no test changes.

## Plan Objective Recap

Per CONTEXT.md, today a fresh-checkout developer running `cp .env.example .env && uv run pytest -m live_homelab tests/smoke/` gets `FileNotFoundError("MCP server command not on PATH: 'homelab-mcp'")` because the example points at a binary that may not be installed. The dev-machine working config uses `uvx homelab-mcp` (zero-install, since `uv` is a hard toolchain dep). This plan ratifies that as the documented default and hardens the repo against two foot-guns: an accidental `git add .` committing machine-specific `config.yaml`, and the canonical spec being absent from the repo despite being cited as source-of-truth by every CONTEXT.md / ROADMAP.md / CLAUDE.md.
