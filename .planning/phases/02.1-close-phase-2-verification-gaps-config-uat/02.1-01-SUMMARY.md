# Phase 02.1 Plan 01: Drop errlog from stdio_client (Windows fileno fix) Summary

**One-liner:** Fixed Windows-fatal `io.UnsupportedOperation: fileno` crash in `McpTestClient.__aenter__` by removing the incompatible `errlog=_LoggerWriter(_log)` kwarg from `stdio_client(...)`, letting the SDK inherit parent stderr per 02.1 D-07 absorb decision.

## What Changed

**Single file modified:** `src/mcp_test_framework/mcp_client.py` (+11 / -3 lines, two atomic commits).

### Task 1 — `fix(02.1-01)` — commit `d3ddba2`
- **Module docstring** (`src/mcp_test_framework/mcp_client.py:15-18`) — replaced the two-line bullet describing `errlog`-routed stderr with a four-line bullet explaining SDK-default parent stderr inheritance and the preserved-but-unwired logger contract.
- **`__aenter__` body** (`src/mcp_test_framework/mcp_client.py:117-119`) — changed:
  ```python
  read, write = await stack.enter_async_context(
      stdio_client(params, errlog=_LoggerWriter(_log))
  )
  ```
  to:
  ```python
  read, write = await stack.enter_async_context(
      stdio_client(params)
  )
  ```
  Rationale (RESEARCH §Critical Finding 2): on Windows, `subprocess.Popen` calls `errwrite = msvcrt.get_osfhandle(stderr.fileno())` (subprocess.py:1420), and `io.TextIOBase` has no fileno. Omitting `errlog=` lets the SDK default to parent stderr inheritance — `subprocess.Popen` no longer calls `.fileno()` on a Python-level wrapper.

### Task 2 — `docs(02.1-01)` — commit `77d8470`
- **Above `class _LoggerWriter`** (`src/mcp_test_framework/mcp_client.py:64-69`) — added 6-line NOTE comment block explaining the class is unwired post-Task-1 and retained as the seed for a future Option-A re-wiring (real `os.pipe` + asyncio reader forwarding to this writer).
- **`tests/unit/test_mcp_client.py`** — UNCHANGED. RETAIN decision means the 2 `_LoggerWriter` unit tests still apply (the class still exists with identical behavior; only its production callsite is gone).
