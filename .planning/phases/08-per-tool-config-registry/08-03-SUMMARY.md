## Final scaffold format (CD-06)

The emitted scaffold has this exact shape:

```
# mcp-test-framework v1.1 starter config -- generated by `mcp-test-framework config-init`.
# Edit and copy to config.yaml; set MCPTF_CONFIG_FILE=./config.yaml.
# See the README "Per-tool configuration" section for field semantics.

# Phase 08 schema version. Only `1` is accepted by this release.
version: 1

# Per-tool config registry (TOOLCFG-01..07). Keys MUST match tool
# names returned by `mcp-test-framework list-tools`. All entries
# below are commented out by default -- this scaffold is a passthrough.
# Uncomment and edit individual fields to opt a tool into skip /
# judges / args.
tools:
  # alpha_tool:
  #   skip: false
  #   skip_reason: ""
  #   call_arguments: {}
  #   judges: [clarity, disambiguation, parameters]

  # zebra_tool:
  #   skip: false
  #   ...
```

**Comment style.** One-space `#` prefix, two-space block indent — mirrors
`config.example.yaml`'s existing convention so a user can paste the file
into version control alongside the existing example without a diff in
trailing whitespace or marker placement.

**Ordering.** Tools are sorted alphabetically by `name` (mirrors
`_format_tools_text` / `_format_tools_json`'s D-list-4 convention from
Phase 05). Stable across runs.

**Reserved-field omission (CD-06).** `setup:` and `depends_on:` (Phase 08
TOOLCFG-03 / D-06; reserved for SEED-004) are intentionally NOT
included in the scaffold. They are dormant in v1.1; surfacing them in the
operator-facing onramp would imply they have runtime effect. They remain
typed on `ToolConfig` so SEED-004 can light them up additively without a
schema migration.

**Empty server tool list.** Returns `tools:\n  {}\n` so the file remains
valid YAML even if the MCP server returns zero tools (defensive — should
not happen with `homelab-mcp`, but `config-init` is intended to be reusable
against other servers).

**Locked rubric IDs.** The commented `judges:` line names the locked v1.1
rubric IDs in the locked order: `[clarity, disambiguation, parameters]`
(per CONTEXT.md `<specifics>` + TOOLCFG-04). When SEED-003 expands the
rubric set in v1.3, this line in the scaffold updates additively.

## Exit-code matrix (smoke-tested)

| Scenario | Exit | Stream | Behavior |
|----------|------|--------|----------|
| Happy path, no flags | 0 | stdout | Scaffold written |
| `--output PATH` (PATH does not exist) | 0 | (no output) | File written |
| `--output PATH` (PATH exists), no `--force` | 2 | stderr | `error: refusing to overwrite existing file: <path> (use --force)`; file unchanged |
| `--output PATH --force` (PATH exists) | 0 | (no output) | File overwritten |
| `--config PATH` (PATH does not exist) | 2 | stderr | `error: --config path not found: <path>` (inherited from `_load_config`) |
| `FileNotFoundError` from MCP discovery | 2 | stderr | Hint string with `MCPTF_CONFIG_FILE` / `config.example.yaml` reference |
| `KeyboardInterrupt` during discovery | 130 | (no output) | Mirrors `list-tools` |
| `--help` | 0 | stdout | Lists `--config`, `--output`/`-o`, `--force` |

The refuse-to-overwrite gate fires BEFORE the subprocess spawn, so a
stale `--output` path doesn't cost a discovery cycle.
