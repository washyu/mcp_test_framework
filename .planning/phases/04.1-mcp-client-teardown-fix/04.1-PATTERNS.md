**Body to REPLACE** (current `fixtures.py:177-185`):
```python
async with AsyncExitStack() as stack:
    client = await stack.enter_async_context(
        McpTestClient(
            config.mcp_server.command,
            config.mcp_server.args,
            config.mcp_server.timeout_seconds,
        )
    )
    yield client
```
This is the bug. The `AsyncExitStack` enters `McpTestClient.__aenter__` on the per-test task that first triggers fixture setup; finalizer task closes the stack — different task → cancel-scope RuntimeError (CONTEXT §problem).

**Body to INSERT — Variant B (recommended per RESEARCH §Open Question #2):**
```python
shutdown = anyio.Event()
params = StdioServerParameters(
    command=config.mcp_server.command,
    args=config.mcp_server.args,
)

async def _owner_task(*, task_status: anyio.abc.TaskStatus[McpTestClient]) -> None:
    # Cancel scope opens AND closes inside this owner task → no Pitfall 1.
    async with (
        stdio_client(params) as (read, write),
        ClientSession(read, write) as session,
    ):
        async with anyio.fail_after(config.mcp_server.timeout_seconds):
            await session.initialize()
        client = McpTestClient._wrap(session)
        task_status.started(client)  # unblocks tg.start, returns `client`
        await shutdown.wait()

async with anyio.create_task_group() as tg:
    client = await tg.start(_owner_task)  # re-raises owner errors here
    try:
        yield client
    finally:
        shutdown.set()  # owner wakes, unwinds stdio_client + ClientSession
```
Source: RESEARCH §Code Examples Variant B (lines 326-361). Exact shape; planner adapts variable names if needed.

**Variant A** (CONTEXT D-01 verbatim sketch) is also acceptable per CONTEXT §Decisions; see RESEARCH lines 260-320 if planner prefers manual `anyio.Event` for ready signaling. Variant B is the recommended default.

**Sibling fixture to LEAVE UNCHANGED** (`fixtures.py:193-209`, the `judge` fixture):

### `src/mcp_test_framework/mcp_client.py` — possibly add `_wrap` classmethod (wrapper)

**Analog:** itself, lines 102-167 (existing `McpTestClient` class).

**Class header to PRESERVE** (`mcp_client.py:102-110`):
```python
class McpTestClient:
    """Async stdio MCP client over the official mcp SDK. See module docstring."""

    def __init__(self, command: str, args: list[str], timeout_seconds: int) -> None:
        self._command = command
        self._args = list(args)
        self._timeout_seconds = timeout_seconds
        self._stack: AsyncExitStack | None = None
        self._session: ClientSession | None = None
```
The instance attributes `_stack` and `_session` already exist; `_wrap` only needs to set `_session` and leave `_stack=None`.

**Existing `__aenter__` / `__aexit__` to LEAVE UNTOUCHED** (`mcp_client.py:112-146`):
These remain functional for the smoke test in `tests/smoke/test_smoke_homelab_mcp.py:62-71` which still uses `async with McpTestClient(...) as client:` — see "READ-ONLY API surface" below. CONTEXT D-04 locks this contract.

**Methods to LEAVE UNTOUCHED** (`mcp_client.py:148-167`):
```python
async def list_tools(self) -> list[Tool]:
    assert self._session is not None, "McpTestClient not entered"
    async with asyncio.timeout(self._timeout_seconds):
        result = await self._session.list_tools()
    return list(result.tools)

async def get_tool(self, name: str) -> Tool: ...
async def call_tool(self, name: str, arguments: dict[str, Any]) -> CallToolResult: ...
```
The `assert self._session is not None` guard already accommodates a `_wrap`-built instance — `_wrap` sets `_session`, so the guard passes. CONTEXT D-04 + RESEARCH A3 (cross-task `ClientSession` use is safe).

**New classmethod to ADD** (no in-tree analog; cleanest minimal addition per RESEARCH §Open Question #1):
```python
@classmethod
def _wrap(cls, session: ClientSession, timeout_seconds: int = 30) -> "McpTestClient":
    """Build an instance pre-bound to a live ClientSession (Phase 4.1 owner-task pattern).

    Skips __aenter__ / AsyncExitStack ownership — caller (the mcp_client
    fixture's owner task) owns stdio_client + ClientSession lifecycle.
    Used ONLY by the session-scoped fixture; smoke tests continue to use
    `async with McpTestClient(...)`. Mixing modes is undefined.
    """
    instance = cls.__new__(cls)
    instance._command = "<wrapped>"
    instance._args = []
    instance._timeout_seconds = timeout_seconds
    instance._stack = None
    instance._session = session
    return instance
```
Planner picks the exact `timeout_seconds` plumbing (passed in by the fixture via `config.mcp_server.timeout_seconds` is the natural choice).

**Open question for the planner** (RESEARCH §Open Questions #1): an alternative is to NOT add `_wrap` and instead have the fixture construct an `McpTestClient(...)` and reach into private attrs. Recommend: add `_wrap` — explicit beats implicit, and tests calling `await client.list_tools()` then work unchanged.
