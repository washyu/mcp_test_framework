**xdist hook ordering (verified per RESEARCH Finding 1)**:

```
1. pytest_cmdline_main(tryfirst=True)  — xdist resolves auto/logical → integer N, sets tx=["popen"]*N
2. pytest_configure(tryfirst=True)     — user plugins (← OUR clamp lands here)
3. pytest_configure (default)          — pytest core
4. pytest_configure(trylast=True)      — xdist registers DSession
5. pytest_sessionstart(trylast=True)   — xdist's DSession.setup_nodes() reads config.option.tx
```

**Load-bearing invariant**: NodeManager.setup_nodes() reads `tx`, NOT `numprocesses`. Mutating only `numprocesses=1` does NOT prevent N workers from spawning. The pin test asserts BOTH attributes are mutated together.

**Banner category**: `UserWarning` (NOT `DeprecationWarning` — the clamp is a runtime mode constraint, not a deprecation). Verified that `pyproject.toml` `[tool.pytest.ini_options]` has no `filterwarnings = ["error::UserWarning"]` that would convert the banner into a hard fail (RESEARCH Finding 6 spot-check).

**Critical naming nit**: the function decorator is `@pytest.hookimpl(tryfirst=True)`, NOT `@pytest.hookimpl(trylast=True)` (that's what xdist uses). The two decorators interact: tryfirst < default < trylast in pytest's hook ordering — user plugins with `tryfirst=True` run BEFORE plugins with `trylast=True`.
