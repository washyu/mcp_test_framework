bare-`Config()` audit deliverable exists but is factually wrong at four call sites. The inline
comments and the audit-doc rows claim bare `Config()` "inherits host_isolation='strict' default",
but `Config.test_code` has been a REQUIRED field with no default since Phase 21.1, so bare
`Config()` raises `pydantic.ValidationError` before any default is evaluated. One of the sites is

demoted to a wrong-reason `pytest.skip`.

`Config(test_code=TestCodeConfig(generated_root='tests/test_code/_generated'))`, hoists the
`_plugin.py` stash assignment + black-box guard inside the `try` so they never run on the
validation-failure path (CR-02 option b), corrects the audit-doc rows to state the truth, and
adds a regression pin so the corrected behavior cannot silently regress.
