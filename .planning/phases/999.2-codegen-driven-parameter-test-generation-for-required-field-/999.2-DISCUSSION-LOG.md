## Questions presented

### Q1: Examples source

**Options presented:**
- A. config.yaml only — extend `tools.<name>.call_arguments` into `tools.<name>.examples:` (list)
- B. pyproject.toml only — `[tool.mcp_test_framework.examples.<tool>]` blocks
- C. Both — config.yaml wins
- D. inputSchema.examples (JSON Schema) — server-declared, zero operator config

**User selected:** A. config.yaml only

**Rationale captured:** Single operator-edit surface; matches the Phase 33 pattern of putting all per-tool config on `ToolConfig`; avoids dual-parsing burden. Inferred but unstated: the user values config locality (same file the operator already opens to set `judges:`, `skip_buckets:`, `call_arguments:`).

### Q2: Missing-examples policy

**Options presented:**
- A. Emit TODO scenario with `pytest.skip()`
- B. Skip silently
- C. Fail loud on regenerate
- D. Emit + auto-skip via `skip_buckets`

**User selected:** A. Emit TODO scenario

**Rationale captured:** Operator-visible scaffolding for every required-field tool; lazy-fill workflow. Rejected B because invisibility hides coverage gaps; rejected C because it forces eager operator decisions; rejected D because auto-modifying `config.yaml` violates SEED-022 (framework reasoning about operator intent).

### Q3: Regeneration semantics

**Options presented:**
- A. Overwrite (with header marker)
- B. Overwrite only if examples changed (hash-compare)
- C. Error on existing, require --force
- D. Merge — preserve operator edits

**User selected:** A. Overwrite with header marker

**Rationale captured:** Matches existing `_generated/<tool>.py` semantics (same header sentinel convention). Operators who need post-codegen customization should hand-author siblings outside `_generated/`, not edit generated files.

### Q4: `examples ↔ skip_buckets` linkage

**Options presented:**
- A. No linkage — independent surfaces
- B. Warn at load time
- C. Error at load time
- D. Defer to a follow-up phase

**User selected:** A. No linkage

**Rationale captured:** SEED-022 — the framework does not reason about whether the operator's choice is internally consistent. The recommended `examples:` + `skip_buckets: ["output"]` pairing is documented in README/LIBRARY-MODE but not enforced by config validation. Deferring (option D) would still leave the door open; option A locks the principle.
