thread `cfg.tools` from the CLI driver into the new `tools_config` kwarg. This is the I/O-owning
counterpart to plan 02's pure-data emitter — `generate()` writes files, `_emit_smoke_scenario` returns
strings.

operator runs it. Without this plan, `_emit_smoke_scenario` is dead code.

Output: `generate()` gains one keyword-only kwarg with `None` default (backward-compat — A1 in
RESEARCH); per-tool loop gains a branch that detects required-field tools and writes the smoke file
alongside the existing `<tool>.py` before the init-last write; CLI passes `cfg.tools` through.
