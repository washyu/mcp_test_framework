## Decisions Made

- **mode='before' on validator:** The validator uses `mode="before"` instead of the plan-specified `mode="after"` because Pydantic v2 validates list items against `dict` before `mode="after"` runs, using dot notation (`examples.1`) instead of the required bracket notation (`examples[1]`). Switching to `mode="before"` fires the custom validator first, preserving the operator-tone error message with bracket-indexed naming. This is a legitimate deviation (Rule 1 — bug fix) — the behavior required by the plan's acceptance criteria demanded this change.
- **No cross-field linkage:** D-04 + SEED-022 strictly enforced — `examples` and `skip_buckets` are independent operator surfaces.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Switched _validate_examples_shape from mode='after' to mode='before'**
- **Found during:** Task 2 (test execution revealed assertion failure)
- **Issue:** With `mode="after"`, Pydantic v2 intercepts non-dict list items before the custom validator runs, emitting `examples.1` (dot notation) instead of `examples[1]` (bracket notation). The test `assert "examples[1]" in str(ei.value)` failed because the error message used dot notation.
- **Fix:** Changed validator to `mode="before"` so it fires before Pydantic's type coercion. Added explicit `isinstance(v, list)` guard to pass non-list values through to Pydantic's own top-level type rejection.
- **Files modified:** `src/mcp_test_framework/models.py`
- **Verification:** All 6 tests pass including `test_examples_rejects_non_dict_item` which asserts `"examples[1]" in str(ei.value)`
- **Committed in:** `f88683d` (Task 2 commit, alongside test file)
