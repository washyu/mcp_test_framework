### `_codegen.py` — new `_emit_smoke_scenario(tool, *, slug, examples) -> str` (pure-data)

**Analog:** `src/mcp_test_framework/test_code/_codegen.py` — same module's `translate_tool()` at lines 466-548 and `_emit_params_body()` at lines 421-455. Pure-data convention: read dicts, emit strings, no filesystem I/O.

**Imports pattern** (lines 24-36 — reuse, no additions needed):

**Pure-data/I-O split convention** (file docstring lines 21-22):
> "Pure-data: this module reads dicts and emits strings. No filesystem I/O in `translate_tool`; `generate` owns `shutil.rmtree` + `write_text`."

**The new `_emit_smoke_scenario` MUST follow this split** — return a `str` (the scenario source) given `tool: Tool`, `slug: str`, and `examples: list[dict[str, Any]] | None`. File writes belong only inside `generate()`.

**Header sentinel convention** (lines 47-72) — the existing `<tool>.py` 4-line block. The smoke file MUST use the same 4-line format so a single grep finds both kinds of generated files (D-03a):
```python

    "# Source: {slug} (serverInfo.name={server_name_repr}, version={server_version_repr})\n"
    "# Regenerated: {timestamp}\n"
    "# Extend by subclassing in tests/test_code/, not by editing this file.\n"
```

Reuse `_render_header(...)` directly — do NOT invent a parallel template. The existing `json.dumps(...)` escaping of `server_name` / `server_version` is the locked V5-input-validation mitigation pattern (file docstring lines 55-72); the smoke emitter inherits it.

**Operator-supplied `examples` values escaping** (mirrors `_render_init` registry-line idiom at lines 582-590):
```python

# containing `"` / newline cannot close the dict-key string literal
# and inject a callable into the registry dict ...

    f"    {json.dumps(tool_name)}: ({params_cls}, {response_cls}),"
```

**Apply to `_EXAMPLES = [...]`:** use `json.dumps(example, indent=4)` per-example (or `repr(example)`) — NEVER raw f-string interpolation of operator values into the generated Python source. This is the V5 + Tampering mitigation cited in RESEARCH §"Security Domain".
