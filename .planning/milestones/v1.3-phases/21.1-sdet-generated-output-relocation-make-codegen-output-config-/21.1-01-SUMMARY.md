# Phase 21.1 Plan 01: SDET generated output relocation — config surface Summary

**SdetConfig sub-model with required `generated_root: Path` lands on top-level Config as a no-default field; missing key routes through the existing SAFE-03 mapper with no new code path; both example YAMLs and the config-init scaffold ship the new key with the recommended `tests/sdet/_generated` convention.**

- **Duration:** ~80 min (incl. cross-cutting test sweep)

## Accomplishments

- `SdetConfig` exists as a frozen, extra=forbid, not-env-routable Pydantic sub-model in `models.py` with exactly one required field (`generated_root: Path`).
- `Config.sdet: SdetConfig` is declared with NO `default_factory` — Pydantic treats it as required; loading any pre-21.1 config raises `ValidationError` that routes through `_emit_operator_error_for_validation` `missing` branch (exit 2, operator-tone, SAFE-03 framing).
- Schema version stays at v2 — additive required field, SAFE-03 message is the migration cue. No `version: 2 → 3` migration shim needed.
- 10 invariant unit tests pin the contract (6 for SdetConfig itself, 4 for Config integration); these are the regression guards future plans 02–04 will build against.
- Both example YAMLs and the `config-init` scaffold include the new key alongside the existing `ollama:` / `mcp_server:` / `version:` blocks, so operators copying any of the three never hit SAFE-03 on first load.

## Decisions Made

See `key-decisions` in the frontmatter. The most load-bearing decisions:
1. **Required-no-default field over defaulted-with-validator** — D-01 wants the framework to refuse silent path invention. A defaulted field, even with a validator, fails this requirement: the operator never sees the absent-key signal.
2. **`Config.yaml` is the only source** — D-02. No `MCPTF_GENERATED_ROOT` env var (`SdetConfig.generated_root` has no `validation_alias`), no `--out` flag on `gen-sdet-classes`. One source of truth.
3. **No schema version bump** — version stays at `2`. SAFE-03 `"config file is missing a required field: sdet"` + `next:` line is sufficient migration guidance per CONTEXT.md `<deferred>` Config-schema-bump entry.

## Deviations from Plan

The plan's scope statement ("Tests still importing the old hardcoded `generated/homelab_mcp` path remain green — they're reworked in Plan 03") underestimated the cross-cutting impact of adding a required-no-default field to `Config`. Making `sdet` required broke every callsite that constructs a bare `Config()` (production code paths AND test helpers building YAML bodies without an `sdet:` block). Plan 01 absorbs the test sweep as Rule 3 (blocking) inline rather than deferring it, since `uv run pytest tests/framework/` would otherwise leave the suite at 56 failures (40 new) instead of the baseline 17.

### Auto-fixed Issues

**1. [Rule 1 — Bug] `_emit_operator_error_for_validation` only inspected `errors[0]`**
- **Found during:** Task 2 (Config wiring)
- **Issue:** A v1 YAML missing the new `sdet:` block produces TWO Pydantic errors (version-mismatch + missing-sdet). Pre-21.1 the mapper picked `errors[0]` — implementation-defined order. After adding the required `sdet`, the missing-sdet error sometimes won the race, silently flipping the rendered output from the LOCKED SAFE-06 v1-migration message to the SAFE-03 missing-required-field message. Regression caught by `test_safe_06_v1_config_emits_locked_migration_message`.
- **Fix:** Mapper now scans ALL errors for the version-mismatch (`loc=="version"` + `"not supported by this build" in msg`) and prefers it over `errors[0]` when found.
- **Files modified:** `src/mcp_test_framework/cli.py`
- **Verification:** `uv run pytest tests/framework/unit/test_cli_errors.py::test_safe_06_v1_config_emits_locked_migration_message tests/framework/unit/test_cli_errors.py::test_safe_06_v1_config_via_env_var_emits_locked_migration_message` exits 0 (both pass).
- **Committed in:** `99137c1` (Task 2 commit)

**2. [Rule 3 — Blocking] Bootstrap `Config()` call sites broke `config-init` / `list-tools` from an unconfigured directory**
- **Found during:** Task 2 (Config wiring)
- **Issue:** `cli.py` has two bootstrap call sites (`Config()` after `_load_config(..., allow_missing=True)`) that need a working `Config` even when no YAML is reachable. With `sdet` required, both call sites raise `ValidationError` before they can emit the scaffold or list tools — making the SAFE-03 recovery command (`config-init -o config.yaml`) unable to recover.
- **Fix:** Added `_BOOTSTRAP_SDET_STUB = SdetConfig(generated_root=Path("tests/sdet/_generated"))` and updated both call sites to `Config(sdet=_BOOTSTRAP_SDET_STUB)`. The stub matches the recommended convention emitted by `_format_tools_yaml_scaffold`, so save-and-rerun is self-consistent.
- **Files modified:** `src/mcp_test_framework/cli.py`
- **Verification:** `test_config_init_fallback_scaffold_no_banned_tokens` passes (was a new failure before this fix); all 17 `test_config_init.py` tests pass.
- **Committed in:** `99137c1`

**3. [Rule 3 — Blocking] `_format_tools_yaml_scaffold` emitted a config that fails its own SAFE-03 check**
- **Found during:** Task 2 (during the bootstrap-path investigation)
- **Issue:** Operators running `config-init -o config.yaml` and re-running would hit SAFE-03 on the file they just generated.
- **Fix:** `_format_tools_yaml_scaffold` now emits the `sdet:` block between `version: 2` and `tools:` with the recommended convention + a 9-line comment block explaining the field. Matches the same shape used in `config.example.yaml` (Task 3) so the three artifacts stay in sync.
- **Files modified:** `src/mcp_test_framework/cli.py`
- **Verification:** YAML emitted by `config-init` parses through `yaml.safe_load` and round-trips through `Config(yaml_file=...)` without raising.
- **Committed in:** `99137c1`

**4. [Rule 3 — Blocking] `_preflight` autouse session fixture broke every framework test**
- **Found during:** Task 2 (running `uv run pytest tests/framework/unit/test_config.py`)
- **Issue:** `_preflight` requested `config` as a direct parameter, so pytest invoked the `config` session fixture BEFORE the live-MCP scope short-circuit could fire. Framework-only test sessions (no `MCPTF_CONFIG_FILE`, no `config.yaml` in CWD) now fail at fixture setup with `ValidationError(sdet missing)`. Every framework unit test was affected.
- **Fix:** `_preflight` no longer takes `config` as a parameter. It uses `request.getfixturevalue("config")` lazily AFTER `_session_needs_preflight(request)` returns True. SAFE-03 still fires for live-MCP tests where it matters; framework self-tests no longer drag a `Config()` invocation into their setup path.
- **Files modified:** `src/mcp_test_framework/fixtures.py`
- **Verification:** `uv run pytest tests/framework/` goes from 56 failed (post-Task-2-pre-fix) to 13 (matching baseline 17 minus the four `test_config_sdet_field` placeholders now passing).
- **Committed in:** `99137c1`

**5. [Rule 3 — Blocking] 11 test files used `_write_config`-style YAML helpers without `sdet`**
- **Found during:** Task 2 (running `uv run pytest tests/framework/`)
- **Issue:** Every test that built a v2 config YAML body without an `sdet:` block now fails on load. `PATTERNS.md` flagged the `_write_config` helper update as Plan 03's scope, but it has cross-test reach and must land in Plan 01 to keep the suite green.
- **Fix:** Bulk-updated 11 test files. Three patterns applied:
  1. YAML bodies built via `+`-concatenated strings — inserted `'sdet:\n  generated_root: "tests/sdet/_generated"\n'` between `mcp_server:` and `tools:`.
  2. `_write_config` payload dicts (e.g. `test_gen_sdet_classes_cli.py`) — added `"sdet": {"generated_root": str(tmp_path / "_generated")}` entry.
  3. Bare `Config()` calls — passed `sdet=SdetConfig(generated_root="tests/sdet/_generated")` (added a module-level `_SDET_STUB` helper to `test_config.py` and `test_homelab_config.py`).
- **Files modified:** 11 test files (see "Modified — test sweep" above).
- **Verification:** Suite-wide framework failures drop from 56 → 13; the 13 remaining are all pre-existing Phase 23 debt (test_migration_doc, test_doc_scrub, test_tool_config v1-schema, test_isolation environmental). The only "new" failure (`test_isolation` ERROR type change) was already an ERROR at baseline, just from a different cause (homelab-mcp not on PATH at baseline; ValidationError now).
- **Committed in:** `99137c1`
