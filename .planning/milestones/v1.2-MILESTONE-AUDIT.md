## Critical Gap

### BLOCKER — Static example configs ship as schema version 1

Phase 13 raised the accepted schema version to 2 (SAFE-06) and emits a LOCKED migration error on v1 loads (`config.py:67-72`). Two operator-facing example files were not migrated to the new schema:

| File | Line | Issue |
|------|------|-------|
| `examples/homelab-mcp.yaml` | 20 | `version: 1` — fresh load triggers SAFE-06 migration error and exit 2 |
| `examples/homelab-mcp.yaml` | 3 | `# Precedence: CLI > env > .env > YAML > defaults.` — contradicts Phase 13 SAFE-05 (`.env` dropped) |
| `config.example.yaml` | 28-29 | `# This release accepts version 1.` + `version: 1` — same migration trap |

**README.md:326** explicitly directs operators to `examples/homelab-mcp.yaml` as the "complete worked reference." An operator following the README:
1. Copies the example to `./config.yaml`
2. Runs `mcp-test-framework run`
3. Hits the SAFE-06 LOCKED migration error as their **first impression** of v1.2

This undermines the entire v1.2 thesis ("clean, domain-correct experience without having to know framework internals"). This is the exact "loud destructive-default trap" Phase 13 was meant to eliminate, silently reintroduced via the example surface. Per-phase verification couldn't catch this because each phase's truth-checks were scoped to its own artifacts — Phase 12 verified the example "exists and is a worked example," Phase 13 verified the loader "rejects v1," neither checked the integration point.

**Fix scope:** ~3-line patch.
- Flip `examples/homelab-mcp.yaml:20` from `version: 1` → `version: 2`
- Strike the `.env` reference at `examples/homelab-mcp.yaml:3`
- Flip `config.example.yaml:29` from `version: 1` → `version: 2` (and update the comment at line 28)
